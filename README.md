# RT-Thread Aicar —— 推箱子智能车调试说明书

## 1. 项目概述

本项目是基于 RT-Thread 实时操作系统的智能推箱子小车，运行于 NXP i.MX RT1064 (ARM Cortex-M7, 600MHz) 平台。小车通过 OpenArt 摄像头获取地图，使用 A* 路径规划 + 混合控制器完成自主导航、推箱子、炸炸弹等任务。

## 2. 硬件平台

| 组件 | 型号/说明 |
|------|-----------|
| 主控 | NXP RT1064DVL6A (600MHz) |
| 传感器 | IMU660RA (九轴IMU)、编码器 x3、DL1A/DL1B TOF、MT9V03X/OV7725 摄像头 |
| 通讯 | 2.4GHz 无线串口模块 (UART8, 115200bps) |
| 驱动 | 三全向轮 (麦克纳姆轮底盘) |
| 调试 | 无线串口 → 逐飞串口助手 (PC 上位机) |
| IDE | MDK-ARM 5.33+ / IAR 8.32.4+ |

## 3. 软件架构

```
RT-Thread OS
├── control 线程 (5ms, 最高优先级)
│   ├── AHRS_Update / Position_Update
│   ├── debug_seekfree_loop()          ← SeekFree 参数轮询
│   ├── HybridController_ComputeControl()
│   └── CarController_SetSpeed / Update
├── debug_exec 线程 (10ms)
│   └── debug_process_commands()       ← 命令出队执行（可阻塞）
├── uart_parse 线程
│   └── 解析 OpenArt 地图数据帧(0xAA55)
├── 任务管理器 (Task Manager)
│   └── 推箱子/炸炸弹任务调度
└── main 初始化
    ├── 时钟 600MHz → 无线串口 → 电机/编码器 → IMU → 位置环
    ├── 混合控制器 → 地图接收 → 数字识别
    ├── 各线程创建并启动 RT-Thread 调度器
    └── debug_module_init()            ← 调试模块初始化（含独立线程）
```

## 4. 调试模块概述

调试模块通过无线串口实现 **零侵入式动态调参**，支持两种交互方式：

- **逐飞串口助手 PC 上位机**：调参面板用 8 通道滑块调节参数，**参数值采用整数传输（×1000 缩放）**
- **串口终端 (PuTTY/MobaXterm)**：文本命令切换参数组、查看状态、执行测试、生成固化代码

两种方式共用同一无线串口，通过回调拦截器自动分离文本和二进制数据，互不冲突。命令执行在独立的 `debug_exec` 线程中，测试函数可安全阻塞而不干扰控制线程。

### 参数值的整数约定

上位机发来/显示的均为 **整数（×1000）**，MCU 内部自动除以 1000 还原为浮点数：

| 上位机滑块值 | MCU 实际值 | 含义 |
|:-----------:|-----------|------|
| 100 | 0.100 | 速度 0.10 m/s |
| 800 | 0.800 | 角度 KP 0.8 |
| 150 | 0.150 | 前视距离 0.15 m |
| 100000 | 100.0 | 轮速 KP 100.0 |

### 禁用调试模块

正式比赛时将 `project/code/debug.h` 中的 `#define DEBUG_ENABLE 1` 改为 `0` 即可，所有调试代码编译为空函数。

## 5. 参数分组与通道映射

全车可调参数分 **3 组**，每组 8 个通道（与逐飞助手通道 0~7 一一对应）：

### 组1：`speed` —— 速度内环

| ch | 参数名 | 默认值(×1000) | 实际值 | 范围(×1000) | 说明 |
|:--:|--------|:-----------:|--------|:----------:|------|
| 0 | INNER_KP | 100000 | 100.0 | 0~500000 | 轮速环 P 增益 |
| 1 | INNER_KI | 2500 | 2.5 | 0~100000 | 轮速环 I 增益 |
| 2 | INNER_KD | 1000 | 1.0 | 0~50000 | 轮速环 D 增益 |
| 3 | NAV_SPD_MAX | 100 | 0.10 | 10~1000 | 导航最大速度 (m/s) |
| 4 | MIN_SPEED | 80 | 0.08 | 10~500 | 最低维持速度 (m/s) |
| 5 | PUSH_SPD_MAX | 80 | 0.08 | 10~1000 | 推箱最大速度 (m/s) |
| 6~7 | — | — | — | — | 保留 |

> **调试目标**：轮子能否跟上速度指令、起步停车是否平稳、极速是否失控。

### 组2：`angle` —— 角度环

| ch | 参数名 | 默认值(×1000) | 实际值 | 范围(×1000) | 说明 |
|:--:|--------|:-----------:|--------|:----------:|------|
| 0 | ANGL_KP | 800 | 0.8 | 0~5000 | 角度环 P 增益 |
| 1 | ANGL_KD | 200 | 0.2 | 0~3000 | 角度环 D 增益 |
| 2~7 | — | — | — | — | 保留 |

> **调试目标**：走直线是否"画龙"（摆动）。KP 越大纠偏越快（过大振荡），KD 抑制超调。

### 组3：`tracking` —— 路径跟踪 + 位置环

| ch | 参数名 | 默认值(×1000) | 实际值 | 范围(×1000) | 说明 |
|:--:|--------|:-----------:|--------|:----------:|------|
| 0 | LOOKAHEAD | 150 | 0.15 | 20~500 | 纯跟踪前视距离 (m) |
| 1 | PATH_TOL | 30 | 0.03 | 5~200 | 路径点到达容差 (m) |
| 2 | MIN_LOOKAHD | 80 | 0.08 | 20~300 | 最小前视距离 (m) |
| 3 | MAX_LOOKAHD | 500 | 0.50 | 100~1000 | 最大前视距离 (m) |
| 4 | POS_KP | 2000 | 2.0 | 0~10000 | 位置环 P 增益 |
| 5 | POS_KD | 800 | 0.8 | 0~5000 | 位置环 D 增益 |
| 6~7 | — | — | — | — | 保留 |

> **调试目标**：A* 路径跟随精度、过弯平滑度、终点停车精度。

## 6. 完整命令参考

### 6.1 参数组管理

| 命令 | 参数 | 效果 |
|------|------|------|
| `map speed` | — | 切换到速度环参数组，上位机 8 通道刷新为轮速 PID + 速度限制 |
| `map angle` | — | 切换到角度环参数组，上位机 8 通道刷新为角度 KP/KD |
| `map tracking` | — | 切换到路径跟踪参数组，上位机 8 通道刷新为前视/容差/位置环 |
| `status` | — | 打印当前组所有通道名、当前值（浮点）和范围 |
| `save` | — | 打印当前组参数的 C 代码初始化语句，可直接粘贴到 `main.c` |

### 6.2 测试命令

| 命令 | 参数 | 效果 | 备注 |
|------|------|------|------|
| `test empty` | — | 加载内置 12×16 空地图（全 `-`） | 配合导航/方形测试使用 |
| `test straight <cm>` | 距离(cm) | 小车从当前位置直行指定厘米，打印终点误差 | 需控制器空闲 |
| `test square <cm>` | 边长(cm) | 沿方形路径走一圈回到起点，打印闭合误差 | 需控制器空闲，建议先 `test empty` |
| `test nav <x_cm> <y_cm>` | 目标坐标(cm) | 使用当前地图规划路径并导航到目标点，打印终点误差 | 需控制器空闲 |
| `test digit` | — | 发起一次 UART4 数字识别，打印识别结果 | 需硬件连接 |
| `test box` | — | 发起一次 UART4 箱子类型识别，打印识别结果 | 需硬件连接 |

### 6.3 辅助命令

| 命令 | 效果 |
|------|------|
| `help` | 打印所有命令列表 |

### 6.4 使用示例

```
test empty              → 加载空地图
test straight 200       → 直行 200cm，验证里程计
test square 100         → 1m 方形路径，验证路径跟踪精度
test nav 150 200        → 导航到 (1.50, 2.00)
test digit              → 识别当前视角的数字
test box                → 识别当前视角的箱子类型
map speed               → 切速度组，开始调轮速 PID
map tracking            → 切路径组，调前视距离
save                    → 输出固化代码
```

## 7. 典型调参工作流

```
1.  上电，等待无线串口打印 "Debug module ready"
2.  test empty                              → 加载空地图
3.  map speed                               → 上位机滑块切到速度组
4.  逐飞助手上位机拖滑块调轮速 PID            → 原地观察轮速响应
5.  map angle                               → 上位机滑块切到角度组
6.  test straight 200                       → 直行 2m，观察是否走偏/画龙
7.  逐飞助手上位机调 ANGL_KP/KD              → 消除摆动
8.  test square 100                         → 走 1m 方形，验证路径跟踪精度
9.  map tracking                            → 上位机滑块切到路径组
10. 逐飞助手上位机调 LOOKAHEAD/PATH_TOL      → 优化过弯和终点精度
11. 重复 6~10 直至满意
12. save                                    → 输出固化代码
13. 将 save 输出粘贴到 main.c 初始化部分       → 重新编译
14. 确认无误后 DEBUG_ENABLE 改为 0            → 编译正式版本
```

## 10. 常见问题

**Q: 上位机滑块值为什么是整数（100、800）而不是 0.10、0.80？**
A: 调试协议使用整数 ×1000 缩放传输，避免浮点编码兼容性问题。上位机滑块值除以 1000 即实际值。

**Q: 逐飞助手滑块拖动后参数没变化？**
A: 确保无线串口已连接。终端发 `status` 确认当前组和通道映射正确。

**Q: `test nav` 报 "Path planning failed"？**
A: 检查是否先执行了 `test empty` 加载地图。在空地图中目标坐标超出范围（>3.2m 或 >2.4m）会失败。

**Q: save 输出代码放哪里？**
A: 放到 `main.c` 中 `HybridController_Init()` 和 `MotorPID_SetGlobalParams()` 之后。

**Q: 如何确认调试模块已启用？**
A: 上电后无线串口打印 `Debug module ready. Group: speed` 及通道参数表。
